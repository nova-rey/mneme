## Code-release verification

The paper's “Responsible release” section says anonymous research code, evaluation scripts, and benchmark assets are released, while excluding a deployment-ready steering service and curated covert banks. However, the versioned arXiv PDF/HTML and source contain no repository URL or named code artifact. The paper's Appendix D says an anonymous repository linked in the abstract contains exact evaluation assets, but that link is not present in the retrieved arXiv v2 abstract/page.

A plausible author-associated candidate was found: [`AndyLiuin/Memory_Inception`](https://github.com/AndyLiuin/Memory_Inception), default branch `main`, inspected at commit `578de36a556cadeb9ea433dee2e153d76e70e0ec` (commit timestamp 2026-05-07 02:26:19Z). The GitHub profile identifies its owner as a Yale ML PhD student; the account also contains a separately named “Spectral-lens-llm-training” project. This supports a likely relationship to the Yale coauthor Andy Zeyi Liu, but the MI paper does not link this account and the MI repository does not identify itself with the arXiv ID; attribution is therefore plausible, not conclusively author-verified. It contains `qwen3_eval` and `vllm_port` code, including canonical-memory and attention-patch files, but has no root README, release/tag, LICENSE file, or GitHub-detected license. The code license is unknown; the paper's CC BY license does not license the repository. The code was shallow-cloned outside the project at `/tmp/mi1-author-repo` for inspection only; no setup or code was executed and no code was copied into MNEME. Do not reuse or redistribute that repository's code unless a compatible license or explicit permission is established.

This source intake therefore supports an independent Gemma port from the published method. It does not support claiming that the authors supplied Gemma/llama.cpp code. If later work establishes the candidate repository's identity and license, update the record additively with the exact source and revision; do not rewrite this finding.

## Published method versus MNEME Gemma port

**Published:** training-free, frozen-backbone, text-derived token-level KV banks; selected attention layers/heads or KV groups; canonical pre-RoPE keys; a selector calibrated on task-specific examples; a bank mixture formulation and a Qwen3/vLLM side-bank approximation; results on Llama 3.1 and Qwen3.

**Proposed MI1 port:** a separately built, local implementation for `google/gemma-4-E4B-it` using the pinned Q2 GGUF and llama.cpp host, with Gemma-specific attention and layer semantics audited from the actual implementation. It must independently define and test bank encoding, slot routing, RoPE and normalization, attachment/removal lifecycle, and the exact attention operator. No published result, selector, code license, or architecture compatibility transfers automatically to this port.
