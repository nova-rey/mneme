# Prospective conversation construction

`construction.json` is the machine-readable schedule. Network and watering are development domains; baking is reserved as the untouched-domain check. Each domain has one shared opening and three ten-turn trajectories: F-new, F-same and S-rephrased. The opening is authored once; Quinn generates the subsequent nine participant messages through the existing shared-partner machinery, receiving the same Gemma reply in both private A/B slots.

Each private turn ledger supplies exact factual sentences and a required conversational action. Quinn must preserve the sentences, including quantities and negation, while phrasing the surrounding question naturally. Public messages contain no condition name, score, validity flag or forced analogy. All patterns use the same preservation rule. S-rephrased factual sentences vary every turn while keeping the same unresolved situation and absence of new tests. F-same varies test results and quantities within a deliberately stable vocabulary. Reversal tests and longer repeats count as authored evidence, not automatic proof of conversational quality.

The pre-Gemma gate requires factual sentences intact and in order and rejects unexplained numeric literals, private-label leakage, divergence and empty output. A failed gate ends and archives the whole trajectory attempt. It is not repaired or spliced. Exact string checks do not establish complete fidelity; Root must read the exchanges and publish a judgment before accessing scores. Gemma may produce useful new approaches even when the participant circles; that is a required source of ambiguity in the judgment.

The preflight is three turns of network F-same and three turns of watering S-rephrased. Main execution requires Root's review of those transcripts and the final frozen construction. Formula freezing is separate and occurs before main scoring. At most two complete replacement trajectories are allowed, using the frozen design and seed offsets 10000 and 20000. The three patterns within each domain share seed coordinates. The Quinn provider does not advertise verified seed control, so its exact requests/results are retained without a deterministic-regeneration claim.

Gemma starts with a 2048-output-token ceiling at temperature 0.35 and top_p 0.9, without a brevity instruction or reasoning change. The resident context is 4096 tokens. The same deterministic context rule starts from two complete prior exchanges and removes the oldest whole exchange until native template rendering/tokenization fits 1792 prompt tokens. Every omitted pair and actual prompt is recorded. This reserves 256 tokens beyond the output allowance. A current input that cannot fit is rejected; individual messages are never clipped. Natural stopping controls actual answer length. Capped output remains an incomplete observation.

The initial frozen D100 CompactStore is read-only. The runner uses promoted CompactRuntime graph/learner/SAA bindings and the existing SAA payload in the ordinary system prompt; no developmental, graph, introspection or metadata write is permitted. Every trajectory starts with the same state. There is one normal extraction call per accepted exchange containing participant and Gemma source slots. No source-specific or metric-specific generation occurs.

The finite ceiling is 335 normal calls and 366208 requested output tokens: 116 Gemma calls at 2048, 116 extractor calls at the existing 768 contract ceiling, and 103 Quinn calls at 384. The specialist extractor is not an autoregressive generator; its contract ceiling is conservatively included. Preflight uses at most 16 calls, nine main trajectories 261, and two replacements 58. Tokenization, source inspection, deterministic gates and measurement use no inference calls.

The source-level headroom and GLiNER coverage investigation is retained in `runtime_preflight.json`. GLiNER's 4096 limit is applied to word-splitter tokens before schema/subword encoding. The exact installed splitter can be counted deterministically. Input coverage and the existing six-proposal adapter capacity are different: omitted proposals make the relevant semantic source view partial even if all text reached GLiNER. Unsupported or unknown coverage stays unavailable.
