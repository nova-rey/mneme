# Frozen prospective conversation construction

The construction in `construction.json` was written before any live call. It fixes two topics, two private conditions per topic, ten accepted turns per conversation, nine private continuation circumstances per condition, and all measurement definitions. The exact same public opening starts F and S within each topic. The definitions were not adjusted after inspecting outputs.

The topics are balcony reservoir-and-wick watering and workshop temperature-sensor connectivity/power troubleshooting. F introduces a sequence of concrete measurements, narrowed alternatives, and practical constraints inside that single problem. S repeatedly revisits the initial uncertainty without new tests or facts. These are authored conditions rather than independently judged conversational quality. There is no third topic-switch control and no repeated-seed replication.

Quinn is the existing `Qwen/Qwen3-30B-A3B` partner through `build_shared_interloper_request`. Its private concerns contain only the circumstance for that turn, not an F/S label. The shared builder requires A/B replies; this study supplies the single preceding Gemma reply in both slots, a degenerate shared environment with no sibling content to leak. Quinn generates one plausible public message. Only that message, Gemma's own preceding two exchanges through existing `subject_history`, the existing system prompt and any normal SAA memory block reach Gemma. Neither condition labels nor private schedules are passed to Gemma. Quinn is never an assessor.

Each conversation forks the same immutable R8 `SAA-developed.sqlite3` checkpoint with the existing read-only `fork_from_checkpoint` API. These are new conversations in disposable descendants, not reruns of a historical campaign. Graph and learner are frozen: the usual controller executes Gemma and the usual GLiNER interpretation service extracts and validates residue, but there is no assessment, publication, introspection or learner update. Consequently extracted structure is not newly earned graph structure. The existing SAA policy remains `field-saa-v1` with matched field seeds. Both F and S use identical Gemma generation seeds by topic/turn, and temperature 0.35, top_p 0.9, maximum 256 output tokens. Quinn retains existing settings (0.7, 0.9, 192); extraction retains its existing deterministic request parameters (0, 768).

The fixed budget is 40 Gemma responses, 40 existing extractor calls and 36 Quinn continuations: 116 normal conversation/extraction calls, zero measurement/judge calls, at most 47,872 requested output tokens. No inference was used for preflight. Resident Gemma and GLiNER health endpoints returned HTTP 200; the configured credential file existed; the DeepInfra TLS port was reachable. No credential value appears in artifacts. The runner never automatically retries uncertain calls and refuses an existing live output directory.

Arc membership uses the existing `declared_conversation_arcs` contract with constant topic keys within each conversation. The record's `turn` is study-local 1–10, while `ordinal` and the declared start/end coordinates come from `episodes.accepted_revision`. This is valid here because no graph/learner publication creates intervening revisions. The accepted-turn ID uses the declared contract; accepted episode and operation IDs are separately retained. Declared arc membership measures persistence, not automatic topic understanding. The optional existing P3 marker-based `_arc_slices` readout is reported separately from the persisted arc contract.

Raw call JSON includes exact requests and returned content/metadata. Validated raw residues and pre-generation field traces are retained without introducing another inference. Extraction failure is null with its validation error; zero returned concepts remains an observed empty extraction, not proof of semantic stagnation. Each descendant's scientific state is compared before/after, and the source checkpoint hash is checked again after the whole run. The original live process checked graph_concepts, graph_edges, graph_routes, learner_values and learner_updates; subsequent runner hardening also requires and hashes graph_snapshots and learner_snapshots. This hardening did not trigger any live rerun.

Run:

```sh
.venv/bin/python tools/run_arc_measurements.py                  # pure plan
.venv/bin/python tools/run_arc_measurements.py --execute --output /tmp/mneme-arc-measurements-v1
.venv/bin/python tools/run_arc_measurements.py --replay docs/experiments/arc_measurements/records.json --output /tmp/arc-replay
```

Replay constructs no hosts. It produces a full scalar CSV matrix, full JSON matrix and readable transcript from recorded evidence. Replaying identical inputs produces byte-identical outputs. Compact checked-in evidence excludes disposable SQLite databases and redundant per-turn copies; the full original run remains under `/tmp/mneme-arc-measurements-v1`.

Realization caveat: manual transcript inspection during the run found that Quinn did not reliably enact the private F circumstances. In particular, later network-F messages remained in a speculative re-sync/load loop instead of consistently introducing the scheduled voltage/cable/battery/access-point evidence. Watering-F also omitted some authored evidence. Thus F/S are intended construction labels, not verified realized classes, and any apparent numerical separation or lack thereof must be interpreted with this fidelity failure. No conversation or metric was revised or rerun in response.
